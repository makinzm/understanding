## Pick Up

1. [Leanstral 1.5: Proof abundance for all](https://mistral.ai/news/leanstral-1-5/)
   - Why I recommend: Mistral's formal-verification-focused model release is high on today's HN front page (351 points) — worth tracking as "LLM-assisted proof" tooling matures alongside mainstream chat/agent models.

   - Why I recommend: A cost/throughput breakdown of GLM-5.2 on AMD hardware — directly actionable for anyone comparing inference cost curves across GPU vendors for production ML workloads.

4. [Build AI Security Agents with Wiz MCP](https://www.wiz.io/blog/introducing-wiz-mcp)
   - Why I recommend: Wiz shipping an MCP server for security agents is a concrete example of the "agent + cloud security" pattern the owner should track as agentic tooling gets wired into infra operations.

5. [MCP Auto-Execution: From Git Clone to Cloud Compromise in Amazon Q VS Code Extension](https://www.wiz.io/blog/amazon-q-vulnerability)
   - Why I recommend: A concrete disclosed vulnerability chain showing how an MCP-enabled coding assistant extension could auto-execute untrusted code from a cloned repo into a cloud compromise — essential threat-model reading for anyone integrating MCP/agent tooling into dev workflows.

6. [kNNGuard: Turning LLM Hidden Activations into a Training-Free Configurable Guardrail](https://arxiv.org/abs/2607.02072)
   - Why I recommend: Proposes a guardrail built directly from an LLM's own hidden activations via kNN, without extra training — a practical, low-cost safety mechanism worth evaluating against existing classifier-based guardrails.

7. [Expander Sparse Autoencoders: Parameter-Efficient Dictionaries for Mechanistic Interpretability](https://arxiv.org/abs/2607.01799)
   - Why I recommend: A parameter-efficiency angle on sparse autoencoders for interpretability — relevant if the owner is evaluating cheaper ways to scale mechanistic-interpretability tooling to larger models.

8. [Many Voices, One Reward: Multi-Role Rubric Generation for LLM Judging and Reward Modeling](https://arxiv.org/abs/2607.01830)
   - Why I recommend: Addresses a real pain point in LLM-as-judge setups — single-rubric bias — by generating multi-role rubrics for reward modeling, directly applicable to anyone building RLHF/eval pipelines.

9. [すでに4800スター、Loop Engineeringとは — "自分の仕事はloopを書くこと"](https://zenn.dev/acntechjp/articles/0c63b5b08bbdb9)
   - Why I recommend: Introduces "Loop Engineering" as a named pattern for agent-loop design (backing a repo with ~4,800 GitHub stars) — useful vocabulary and reference implementation for anyone building agentic systems around iterative tool-use loops.
