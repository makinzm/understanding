### Issues encountered

- **Reddit blocked entirely**: All 11 subreddit requests to `old.reddit.com` returned `HTTP Error 403: Blocked`. This looks like an IP/User-Agent block on the fetch environment rather than a data problem — per the compliance notes, the source was skipped gracefully and no Reddit content is included in this report.
- **`scripts/fetch_trends.py` had several real bugs that were fixed as part of this run** (verified by re-fetching and diffing before/after output):
  - Progress/error log lines were printed to stdout via `print(..., flush=True)`, which corrupted the JSON when following the documented `python3 scripts/fetch_trends.py > /tmp/trends-data.json` invocation. Logging now goes to stderr via a `log()` helper, leaving stdout as pure JSON.
  - Hatena fetch used `https://b.hatena.ne.jp/hotentry/it` (the HTML page) instead of the documented RSS endpoint `https://b.hatena.ne.jp/hotentry/it.rss`, so `ET.fromstring()` failed on the HTML with "not well-formed (invalid token)" and 0 bookmarks were returned. Fixed to use the `.rss` URL.
  - Hatena's RSS is RSS 1.0/RDF and declares a default XML namespace, so `root.findall(".//item")` (unnamespaced) matched nothing even once the correct URL was fetched. Fixed to match elements by local tag name regardless of namespace.
  - Hatena bookmark counts were derived by regex-scanning the item `<description>` for the first digit sequence — this actually picked up unrelated numbers (e.g., a date like "2026年7月31日" inside the article text), producing a fabricated count like "2026 bookmarks" for an article that has nothing to do with that number. Since the feed has no real bookmark-count field, this was removed in favor of reporting the count as unavailable (see Hatena table above) rather than showing an invented number.
  - The arXiv `cs.LG/recent` listing scraper's regexes assumed double-quoted HTML attributes (`href="..."`, `class="..."`), but arXiv's current listing page mixes single/double quotes (`class='list-title mathjax'`) and has a stray space in `href ="/abs/..."`. Both regexes were tightened to tolerate either quote style and whitespace around `=`; before the fix this returned 0 papers, after the fix it returns 50.
  - arXiv titles containing HTML entities (e.g., `&#39;`) were passed through unescaped in the JSON output (e.g., `Newton&#39;s algorithm`). Fixed by unescaping with `html.unescape()`.
  - Wiz Blog title extraction called `.lstrip("<![CDATA[").rstrip("]]>")` on already-CDATA-decoded text. `str.lstrip`/`str.rstrip` treat their argument as a *character set*, not a literal prefix, so this silently ate real leading letters from titles starting with characters in `{<, !, [, C, D, A, T}` — e.g. "The Wiz Red Agent is Now Generally Available" became "he Wiz Red Agent is Now Generally Available". Fixed by removing the unnecessary strip call (ElementTree already decodes CDATA).
  - Wiz Blog's RSS feed returns its entire ~657-post history (not just recent posts), which would have dumped years of archive into a "daily" report. Since the feed is ordered newest-first, fetching is now capped to the 20 most recent entries.
  - `datetime.utcnow()` (deprecated) was replaced with `datetime.now(timezone.utc)`.

These were genuine bugs preventing real data collection (Hatena and arXiv returned 0 results before the fixes) or causing incorrect data to be reported (corrupted Wiz titles, fabricated Hatena bookmark counts, unescaped HTML entities in arXiv titles) — not scope creep unrelated to this task. All fixes were verified by re-running the script end-to-end and comparing output before/after.
