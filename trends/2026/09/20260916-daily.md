# Daily AI & Tech Trends - 2026-09-16

## Pick Up

1. [Training a 4B model to produce 81% faster query plans than Postgres](https://rohanbansal.com/qorl)
   - Why I recommend: Today's top-scoring ML-relevant HN post (334 pts) — a concrete case of a small fine-tuned model outperforming a mature heuristic optimizer (Postgres' query planner), a useful pattern for anyone considering learned components inside classically-engineered systems.

2. [Off Guard: Breaking LiteLLM from authentication bypass to cloud compromise](https://www.wiz.io/blog/off-guard-breaking-litellm-from-authentication-bypass-to-cloud-compromise)
   - Why I recommend: LiteLLM is a widely used LLM gateway/router in production ML stacks; this shows default keys and unauthenticated MCP sessions chaining to root-level RCE and IAM credential theft — worth auditing before relying on it for multi-provider routing.

3. [Inside 90 days of attacks on AI infrastructure](https://www.wiz.io/blog/ai-infrastructure-honeypot)
   - Why I recommend: Honeypot data on real-world attack campaigns against LiteLLM, MCP servers, and AI frameworks (RCE, blind prompt injection, memory credential theft) — concrete threat intel for hardening any agentic pipeline exposed to a network boundary.

4. [Breaking the 1.58-bit Barrier for Ternary LLMs](https://arxiv.org/abs/2609.16338)
   - Why I recommend: A #2-ranked arXiv-linked HN post on ternary quantization — directly actionable for reducing inference memory/compute cost, an active area given the push toward cheaper on-device and edge LLM deployment.

5. [Dream-RSI: Recursive Self-Improvement through Evolving Worlds](https://arxiv.org/abs/2609.14858)
   - Why I recommend: Explores agents that recursively improve by training against self-generated, evolving environments — relevant groundwork for anyone evaluating self-improving agent loops rather than static fine-tuning.

6. [LoopSpec: Pipelined Self-Speculative Decoding for Looped Transformers](https://arxiv.org/abs/2609.17184)
   - Why I recommend: A concrete inference-efficiency technique combining looped-transformer architectures with self-speculative decoding — the kind of serving-latency optimization that translates directly into lower production inference cost.

7. [Large Language Models Develop Belief State Geometry In-Context](https://arxiv.org/abs/2609.17376)
   - Why I recommend: An interpretability result on how in-context learning organizes belief states geometrically inside LLM activations — useful theoretical grounding for anyone probing what in-context learning is actually doing internally.

8. [Claude Codeで開発期間を2.5か月から1か月に縮めた「ハーネス」の設計手法 - SmartHR Tech Blog](https://tech.smarthr.jp/entry/2026/09/16/110205) (How a "harness" design cut Claude Code development time from 2.5 months to 1 month)
   - Why I recommend: A concrete, measured case study of agent-harness design directly speeding up delivery with Claude Code — practical engineering patterns worth comparing against this repo's own workflow/skill setup.

9. [「APIキーは.envに」はもはや通用しない　AIエージェントの"内通者化"をどう防ぐ？](https://atmarkit.itmedia.co.jp/ait/articles/2609/17/news006.html) (".env" is no longer enough — how to prevent AI agents from becoming "insider threats")
   - Why I recommend: Frames agent tool/credential access as an insider-threat problem rather than a simple secrets-management one, which matches the trust-boundary concerns raised by the Wiz LiteLLM/MCP research above — good to read together.

10. [Sakana AIが「誤差逆伝播なし」でAIを訓練する手法を公開 — 1000層のネットワークでもバックプロップと2ポイント差以内](https://ai.freelance-job.com/article/6aa8792e3e0b24377905cb43) (Sakana AI publishes a backprop-free training method — within 2 points of backprop even at 1000 layers)
